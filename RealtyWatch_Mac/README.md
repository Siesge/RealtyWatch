# RealtyWatch для macOS

Форк Windows-версии (она лежит в `RealtyWatch_Win/` и здесь не меняется). Собирается в обычное
приложение `RealtyWatch.app`: иконка в «Программах», двойной клик, окно — как у любой маковской программы.

Что внутри то же самое: сбор объявлений с ЦИАН, Авито и Яндекс Недвижимости, автоматическое и ручное
объединение и разделение карточек, красный круг на карте и локальный кэш тайлов, история цен,
расписание по часам и по дням недели, автоповтор и продолжение прерванного сбора с контрольной точки,
снятие с продажи по квартире целиком, очистка данных с резервными копиями, выборочный обмен пакетами
карточек (`.rwcards.zip`) со вкладкой «Импорт» и многопользовательскими заметками, прямой обмен
по локальной сети (LAN) с PIN-сопряжением, автопоиском устройств, диагностикой сети и VPN,
Live-режимом, подсветкой квартиры партнёру (Spotlight), обменом лайками/дизлайками/заметками и
шторкой истории событий, экспорт избранного одной автономной веб-страницей, дизлайки («Скрытые»),
личные заметки, распознавание перевыставлений с новой ценой, фильтры по площади кухни и году
постройки дома, наборы фильтров и окно «О программе» с лицензиями по клику на логотип.

Как сделать такой же порт из следующей версии — [PORTING.md](PORTING.md): что переписывать и почему,
где тестировать, как выпускать и что передать конечному пользователю.

## Как собрать и запустить на Mac

```bash
cd RealtyWatch_Mac
./build_app.sh            # соберёт dist/RealtyWatch.app
open dist                 # перетащите приложение в «Программы»
```

Первый запуск сам доставит среду выполнения в `~/Library/Application Support/RealtyWatch`:
Python 3.12, библиотеки и Chromium. На диске это 768 МБ — браузер 465 МБ, Python с библиотеками
303 МБ (`du` в прогоне на Маке). Скачивает меньше, но точного числа нет: в журнале видны только
архивы браузера, 210 МБ, а сколько тянут Python и библиотеки, установщик не печатает — в его
сообщении стоит «около 300 МБ», и это оценка. Всё видно в окне Терминала, после «готово»
программа откроется сама. Дальше запуск мгновенный.

Для разработки сборка не нужна — `./start.command` (или `bash bin/launch.sh`) запускает то же самое
из папки с исходниками. Тесты — `tests/run_tests.command`.

## Где что лежит

| Где | Что |
|---|---|
| `RealtyWatch.app` | только код: `app/`, `web/`, `assets/`, `bin/` — около 2 МБ |
| `~/Library/Application Support/RealtyWatch/` | всё, что программа пишет |
| `…/database/` | `realty.db`, фотографии, кэш тайлов карты `tiles/`, `settings.json` — это и есть база |
| `…/runtime/`, `…/browsers/` | Python и Chromium, их приносит `bin/bootstrap.sh` |
| `…/profiles/` | профили браузера и cookies, привязаны к этому компьютеру |
| `…/logs/` | журналы прогонов и локальной сети (`lan.log`) |

Бандл не пишет внутрь себя — так принято на macOS и так не ломается подпись. Рабочую папку можно
задать переменной `RW_HOME` (например, чтобы держать всё на внешнем диске).

## Как удалить

Приложение лежит в «Программах», всё остальное — в одной папке:

1. Перетащить `RealtyWatch.app` из «Программ» в Корзину.
2. В Finder нажать ⇧⌘G, вставить `~/Library/Application Support/RealtyWatch` — и эту папку тоже в Корзину.

Больше нигде ничего не остаётся: Python, Chromium, база, журналы и профили лежат внутри неё, кеш
установщика — там же и стирается сразу после установки. Прогон на Маке это проверяет отдельным шагом.
Если база нужна, перед удалением сохраните `database/` или сделайте экспорт в самой программе.

## Отличия от Windows-версии

- **Значка в строке меню нет,** и настройки «сворачивать по закрытию» тоже. На macOS и окно
  (pywebview), и значок (pystray) требуют главный цикл приложения — вместе они не уживаются.
  Поэтому «Закрыть» закрывает программу, а уведомления о рынке приходят системные —
  им значок не нужен, так что на Mac они работают всегда.
- **Расписание ждёт только открытую программу.** На Windows она может жить в трее и дождаться
  своего времени; здесь «Закрыть» её закрывает, так что ночной запуск по расписанию случится
  лишь при открытом окне (свёрнутое в Dock — открытое). Если программа была закрыта, пропущенный
  запуск начнётся сам через полторы минуты после старта — но только с галочкой «Догонять
  пропущенный запуск» в окне «Расписание…», а по умолчанию она выключена.
- **Резервные копии удаляются в Корзину macOS.** На Windows об этом просят оболочку системы,
  здесь — `NSFileManager`, Finder или, если ни то ни другое не отвечает, перенос в `~/.Trash`
  своими руками (тогда Finder не предложит «Положить обратно», но копию из Корзины достать можно).
  Не вышло ни одним способом — файл стирается насовсем, и программа пишет об этом прямо.
- **Номер версии** окно «О программе» берёт из `version.txt`, который кладёт в бандл `build_app.sh`.
  При запуске из папки с исходниками файла нет — версия не показывается.
- **Режим «скрытое окно» браузера показывает окно.** macOS не даёт увести окно за край экрана:
  оно открывается в дальнем углу и не выходит вперёд. Если мешает — в настройках есть «без окна».
- **Иконку и имя** приложение берёт из `Info.plist` бандла, а не из кода.
- **Автообновление самой программы с GitHub есть только на Windows.** На macOS обновление ставится
  обычным перетаскиванием нового `RealtyWatch.app` из `RealtyWatch.dmg` поверх старого в «Программах»:
  база данных, фотографии, заметки, избранное, сопряжённые LAN-устройства и настройки лежат отдельно
  в `~/Library/Application Support/RealtyWatch` и полностью сохраняются.

## Передача другому человеку

Приложение не подписано сертификатом Developer ID (членство в Apple Developer Program, $99 в год),
поэтому macOS встречает скачанное приложение предупреждением. Варианты, по возрастанию удобства:

1. **Собрать на том же Mac** (`./build_app.sh`) — метки карантина нет, открывается сразу. Лучший способ.
2. **Переслать `RealtyWatch.dmg`** — его делает `./build_dmg.sh`, и он же лежит артефактом
   каждого прогона на GitHub. Получатель открывает образ двойным кликом и перетаскивает
   приложение в «Программы». Первый запуск: закрыть предупреждение кнопкой «Отменить» —
   из него самого ничего не открыть, — а затем «Системные настройки» →
   «Конфиденциальность и безопасность» → внизу «Открыть всё равно». В macOS 15 Sequoia и новее
   обхода через правый клик больше нет; кому привычен Терминал, тому быстрее
   `xattr -dr com.apple.quarantine /Applications/RealtyWatch.app`.
3. **Купить Developer ID и нотаризовать** — тогда двойной клик работает у всех без оговорок.

Подробный разбор вариантов упаковки и подписи — в [PORT.md](PORT.md),
пошаговый порядок работы — в [PORTING.md](PORTING.md).

## Проверка на настоящем Mac

`.github/workflows/mac.yml` прогоняет на раннере GitHub (настоящее железо Apple, Apple Silicon)
всю цепочку: доставку среды, тесты, сборку `.app` и запуск сервера. Готовое приложение остаётся
артефактом сборки.

Прогон бывает двух видов. Пуш с кодом гонит быстрый набор и всю сборку — это около минуты.
Браузерные тесты, те, что поднимают настоящий Chromium, гонятся по кнопке «Run workflow» и тем
же запуском, которым собирается релизный `.dmg`, то есть перед каждым выпуском; с ними прогон
идёт почти пять минут. Правка одних записей не запускает ничего. Причина простая: репозиторий
приватный, а минуты macOS в Actions считаются с коэффициентом 10.

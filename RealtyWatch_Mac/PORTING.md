# Как сделать порт на macOS из любой версии

Инструкция для следующего раза: в `RealtyWatch_Win/` появилась версия 2, нужен такой же
`RealtyWatch.app` для Mac. Здесь всё, что для этого нужно знать, — чтобы не исследовать заново.
Разведка вариантов упаковки, из которой выросли эти решения, осталась в [PORT.md](PORT.md);
читать её для работы не обязательно.

Сколько это занимает: правки в коде — час-полтора, если версия 2 не переписала `main.py` целиком.
Остальное (оболочка, сборка, релиз) переносится почти без изменений.

---

## 0. Главный принцип

**Системно-зависимого кода в программе ровно один файл — `app/system.py`.** Всё остальное
(сборщики, база, расписание, веб-интерфейс) кросс-платформенно и переносится байт в байт.
Порт — это не «переписать программу под Mac», а:

1. вынести обращения к Windows в `app/system.py` и добавить туда ветку macOS;
2. развести папку с кодом и папку с данными (`.app` не имеет права писать внутрь себя);
3. завернуть всё это в бандл и написать установщик среды.

Отсюда и порядок работы ниже. Код форка при этом остаётся работоспособным и на Windows —
это не побочный эффект, а условие: на Windows удобно гонять тесты, не относящиеся к системе.

## 1. Правила папок — нарушать нельзя

| Папка | Правило |
|---|---|
| `RealtyWatch_Win/` | **только чтение.** Никогда ничего не менять, не перемещать, не форматировать. Читать — можно и нужно |
| `RealtyWatch_Mac/` | рабочая папка порта, здесь всё и меняется |
| корень репозитория | можно: `.github/`, `.gitattributes`, `.gitignore` |

Проверка после каждого коммита — должна быть пустой:

```bash
git status --porcelain -- RealtyWatch_Win
```

Если версия 2 живёт не в `RealtyWatch_Win/`, а в другой папке или ветке — правило то же:
исходник только читается, порт живёт в своей папке.

## 2. Из чего состоит программа

### Переносится как есть — ничего делать не надо

| Компонент | Зачем | Почему переносится |
|---|---|---|
| FastAPI + uvicorn | локальный сервер и API | чистый Python |
| SQLite (`realty.db`) | база объявлений | в стандартной библиотеке |
| `curl_cffi` | запросы к сайтам с отпечатком настоящего браузера | есть колёса под `arm64` macOS |
| `patchright` + Chromium | браузер для Авито и капчи | Chromium качается под нужный процессор сам |
| `lxml`, `pillow` | разбор страниц, фотографии | колёса под `arm64` есть |
| `pywebview` | окно программы | на Windows это WebView2, на macOS — WebKit, тем же кодом |
| `web/` целиком | интерфейс, карта, графики | это просто страница |
| `app/db.py`, `scrapers/`, `rules.py`, `geo.py`, `history.py`, `images.py`, `dedupe.py`, `runner.py`, `scheduler.py`, `runlog.py`, `purge.py`, `offsale.py`, `settings.py`, `transfer.py`, `captcha.py`, `human.py` | вся суть программы | системных вызовов там нет |

### Не переносится — что было и что вместо

| Было на Windows | Почему не работает | Что вместо |
|---|---|---|
| `pystray` + `app/tray.py` (значок в трее) | на macOS и окно, и значок требуют главный цикл приложения — вместе не уживаются | **значка нет.** Уведомления — системные, через `osascript` |
| `pythonnet` | нужен был только для `pystray` | убрать из `requirements.txt` |
| `winsound.Beep` | только Windows | `afplay /System/Library/Sounds/Glass.aiff` |
| `msvcrt.locking` (одна копия программы) | только Windows | `fcntl.flock` |
| `winreg` (светлая/тёмная тема) | только Windows | `osascript` → `dark mode` |
| `ctypes.windll.user32.MessageBoxW` | только Windows | `osascript` → `display alert` |
| `ctypes` + `WM_SETICON`, `SetCurrentProcessExplicitAppUserModelID` | иконка и группа в панели задач | иконку даёт `Info.plist` бандла, этот код просто удаляется |
| `os.startfile` (открыть папку) | только Windows | `open <путь>` |
| `app/trash.py` целиком: `ctypes` + `SHFileOperationW`, `SHQueryRecycleBinW` (удаление резервных копий в корзину) | только Windows | **переписать**, см. ниже. Имена функций и то, что они возвращают, сохранить: на них опираются `transfer.py`, `server.py` и тесты |
| `ctypes` + `FindWindowW`/`SetForegroundWindow` (поднять окно браузера) | только Windows | `open -a Chromium.app`, запасной путь — `System Events` по pid |
| `--window-position=-32000,-32000` (скрытое окно браузера) | оконный сервер macOS возвращает окно на экран | окно в дальнем углу, которое не выводится вперёд |
| `setup.ps1`, `setup.bat`, `start.bat` | PowerShell и `.bat` | `bin/bootstrap.sh`, `bin/launch.sh`, `start.command` |
| `launcher/RealtyWatch.cs` + `RealtyWatch.exe` | обёртка на C# вокруг `pythonw.exe` | `RealtyWatch.app` (способ «appify»), собирается `build_app.sh` |
| портативность: всё внутри папки программы | `.app` в «Программах» не должен писать внутрь себя — и это ломает подпись | данные в `~/Library/Application Support/RealtyWatch` |

### Что добавляется — восемь файлов

| Файл | Что делает |
|---|---|
| `app/system.py` | **все** системные вызовы, с ветками macOS и Windows |
| `bin/bootstrap.sh` | установщик среды: uv, Python, библиотеки, Chromium |
| `bin/launch.sh` | он же `Contents/MacOS/RealtyWatch` — точка входа бандла |
| `build_app.sh` | собирает `RealtyWatch.app` |
| `build_dmg.sh` | собирает `RealtyWatch.dmg` — то, что пересылают |
| `start.command` | запуск из папки с исходниками, двойным кликом (для разработки) |
| `tests/run_tests.command` | тесты двойным кликом |
| `tests/test_system.py` | тесты на `app/system.py` |

Плюс в корне репозитория: `.github/workflows/mac.yml` (проверка на настоящем Mac) и строки в
`.gitattributes` / `.gitignore`.

## 3. Шаг 1. Создать форк

```bash
cd D:/Claude/RealtyWatch
cp -R RealtyWatch_Win RealtyWatch_Mac2          # или новая папка под версию 2
rm -rf RealtyWatch_Mac2/{runtime,browsers,data,database,exports,profiles,logs,launcher}
rm -f  RealtyWatch_Mac2/{setup.bat,setup.ps1,start.bat,RealtyWatch.exe}
rm -f  RealtyWatch_Mac2/app/tray.py RealtyWatch_Mac2/tests/run_tests.bat
find RealtyWatch_Mac2 -name __pycache__ -type d -prune -exec rm -rf {} +
```

Затем скопировать из этого форка восемь файлов из таблицы выше — они почти не зависят от версии
программы (что в них придётся поправить, сказано в разделе 5).

**`.gitattributes` — сделать сразу, до первого коммита:**

```
RealtyWatch_Mac2/** text=auto eol=lf
.github/workflows/*.yml text eol=lf
```

Без этого git положит в репозиторий скрипты с CRLF, и на Mac они не запустятся:
интерпретатор увидит `/bin/bash^M` и скажет `bad interpreter`. Ошибка выглядит как поломка
Mac, а причина — перевод строки.

**Права на запуск** — git их помнит, но только если выставить:

```bash
git update-index --chmod=+x RealtyWatch_Mac2/bin/bootstrap.sh \
  RealtyWatch_Mac2/bin/launch.sh RealtyWatch_Mac2/build_app.sh \
  RealtyWatch_Mac2/build_dmg.sh RealtyWatch_Mac2/start.command \
  RealtyWatch_Mac2/tests/run_tests.command
```

Проверка: `git ls-files -s RealtyWatch_Mac2 | grep -E '\.(sh|command)$'` — должно быть `100755`.

**`.gitignore`** — добавить блок про новую папку (`runtime/`, `browsers/`, `data/`, `database/`,
`exports/`, `profiles/`, `logs/`). `dist/` уже игнорируется на любой глубине.

## 4. Шаг 2. Правки в коде — по файлу

Порядок важен: `system.py` и `paths.py` первыми, остальное опирается на них.

### `app/system.py` — скопировать из прошлого форка целиком

Файл не зависит от версии программы. В нём: `MAC`/`WIN`, `message`, `single_instance`,
`light_theme`, `open_folder`, `beep`, `notify`, `raise_app` и вспомогательные `_osascript`, `_q`.
Правило внутри: **ничего из этого не имеет права уронить программу.** Не вышло подать звук или
поднять окно — значит, не вышло; возвращаем `False` и идём дальше. Пользователь не должен терять
прогон сбора из-за того, что система не дала сыграть звук.

Если версия 2 завела новый системный вызов — он тоже сюда, а не в вызывающий файл.

### `app/paths.py` — развести код и данные

Это главная правка. Было: всё относительно папки программы. Стало: код — рядом с собой,
данные — в рабочей папке.

```python
ROOT = Path(__file__).resolve().parent.parent          # код программы
WEB = ROOT / "web"
ASSETS = ROOT / "assets"


def _home():
    if os.environ.get("RW_HOME"):
        return Path(os.environ["RW_HOME"]).expanduser()
    if sys.platform == "darwin":
        return Path.home() / "Library" / "Application Support" / "RealtyWatch"
    return ROOT


HOME = _home()                                          # всё, что программа пишет
DB_DIR = HOME / "database"
IMAGES = DB_DIR / "images"
BACKUPS = DB_DIR / "backups"
EXPORTS = HOME / "exports"
DATA = HOME / "data"
PROFILES = HOME / "profiles"
LOGS = HOME / "logs"
BROWSERS = HOME / "browsers"
```

Три вещи, которые тут важны:

- `RW_HOME` — не для красоты. Ею пользуются тесты (чтобы не касаться настоящей базы) и человек,
  который хочет держать базу на внешнем диске. На Windows без `RW_HOME` всё остаётся как было —
  портативность не теряется.
- `WEB` и `ASSETS` считаются от `ROOT`, а не от `HOME`: это код, он внутри бандла.
- После правки найти в новой версии всё, что пишет по `ROOT`:
  ```bash
  grep -rn "ROOT" RealtyWatch_Mac2/app --include='*.py' | grep -v paths.py
  ```
  Каждое попадание — решение: это чтение кода (оставить) или запись (перевести на `HOME`).

### `app/main.py` — снять оболочку Windows

Удаляется:

- `import` и использование `tray.Tray`, вся функция `on_shown`, `window.events.minimized += tray.hide`,
  `tray.stop()` в `finally`, параметр `tray` у `_notify_hook`;
- `_set_app_id()` — группа в панели задач, на macOS не нужна;
- `_apply_icon()` — подмена иконки через `WM_SETICON`; на macOS иконку даёт `Info.plist`.

Заменяется на вызовы `system`:

```python
def _message(text):          return system.message(text)
def _single_instance():      return system.single_instance(LOCK_FILE)
def _light_theme():          return system.light_theme()
def _notify(title, text):    return system.notify(title, text)
```

`os.startfile(...)` в `DesktopApi.open_db_folder` и `open_logs_folder` → `system.open_folder(...)`.

Уведомление о капче раньше вешалось на значок в трее, теперь — на системное уведомление, и его
можно поставить сразу, не дожидаясь `window.events.shown`:

```python
manager.on_launch_done.append(_notify_hook())
from . import alerts
alerts.on_human_needed(lambda title, text: _notify(f"RealtyWatch — {title}", text))
webview.start(private_mode=False, storage_path=str(paths.DATA / "webview"))
```

И мелочь, которую легко забыть: в сообщении об ошибке путь `logs\console.log` → `logs/console.log`.

### `app/alerts.py` — звук

`winsound.Beep` → `system.beep(notes)`. Частоты на macOS задать нельзя, поэтому `system.beep`
проигрывает системный звук столько раз, сколько нот в списке. Заодно поправить комментарии:
режим «без звука» на Windows глушил и звук уведомлений, на macOS уведомления продолжают
показываться беззвучно сами.

### `app/server.py`

```python
from . import alerts, db, ..., settings, system, transfer   # добавить system
...
@app.post("/api/logs/open")
def logs_open():
    system.open_folder(paths.LOGS)
```

### `app/trash.py` — корзина, написать заново

Единственный файл, который приходится писать с нуля: на Windows удаление в корзину делает одна
команда оболочки, на macOS такой одной команды нет. Внешность сохранить ровно, остальной код
обращается только к ней:

```python
available(path) -> bool      # есть ли куда положить файл с этого пути
count(path) -> int | None    # сколько лежит в Корзине этого тома (None — посмотреть не удалось)
delete(paths) -> (n, trashed)  # trashed говорит, в Корзину ушло или стёрлось насовсем
_to_trash(files) -> bool     # единственное место, которое трогает Корзину
```

Внутри — три способа по очереди, от родного к грубому, потому что заранее не известно, что принесла
с собой сборка:

1. **`NSFileManager.trashItemAtURL_resultingItemURL_error_`** через pyobjc. Родной способ: Finder
   помнит, откуда файл, и предлагает «Положить обратно». pyobjc приходит вместе с `pywebview`,
   но закладываться на это нельзя — список библиотек может поменяться, а падать из-за корзины нельзя.
2. **Finder через `osascript`**: `tell application "Finder" to delete {POSIX file "…"}`. Тоже помнит,
   откуда файл. Finder на macOS работает всегда, и без `activate` он не выходит поверх окна программы.
3. **Перенос в `~/.Trash` своими руками.** «Положить обратно» Finder уже не предложит, но из Корзины
   файл видно и достать можно — а в этом и был смысл. Имя занято — рядом кладётся «копия 2.zip»,
   как делает сам Finder. Только в пределах тома: перенос на другой диск был бы копированием.

Две ямы, в которые легко попасть:

- **`~/.Trash` может не существовать.** На свежем Маке (и на раннере CI) папки нет, пока в Корзину
  впервые что-то не положат — создаёт её система. Если `available()` отвечает «нет» только потому,
  что папки ещё нет, Корзина не заработает никогда. Поэтому для домашнего тома достаточно права
  писать в домашнюю папку, а `_move_trash` создаёт папку сам.
- **У каждого тома Корзина своя.** Для внешнего диска это `.Trashes/<uid>` в корне тома, и её
  программа за систему не создаёт. Том определяется по `st_dev`: вверх по дереву, пока он не сменится.

`_to_trash` подменяют в тестах пустышкой — Корзину хозяина трогать нельзя:

```python
real = trash._to_trash
trash._to_trash = lambda files: False
self.addCleanup(setattr, trash, "_to_trash", real)
```

Чем именно будет удалять **этот** Mac, видно в прогоне: шаг «Корзина macOS» печатает `trash.route()`
и падает, если не доступен ни один способ.

### `app/net.py` — окно браузера

Две правки, обе про окна.

**Аргументы Chromium** вынести в функцию — на macOS окно нельзя увести за край экрана:

```python
def _window_args(window):
    if window == "visible":
        args = ["--start-maximized"]
    elif system.MAC:
        args = ["--window-position=2200,1200", "--window-size=1440,900"]
    else:
        args = [f"--window-position={OFFSCREEN},{OFFSCREEN}", "--window-size=1440,900",
                "--disable-features=CalculateNativeWinOcclusion"]
    args += ["--disable-backgrounding-occluded-windows", "--disable-renderer-backgrounding",
             "--test-type"]
    return args
```

`--test-type` нужен на обеих системах: он убирает полосу «unsupported command-line flag», которую
Chromium показывает из-за флага `--disable-blink-features=AutomationControlled` (его ставит сам
patchright, и он нужен — без него `navigator.webdriver = true`).

**Поднять окно браузера** поверх окна программы (капча ждёт человека):

```python
def raise_window(self, left=80, top=60):
    if system.MAC:
        app = self._chromium_app()
        if app and system.raise_app(app):
            return
        pid = self._browser_pid()
        if pid:
            system.raise_app(pid)
        return
    ...  # дальше прежняя ветка Windows
```

`_chromium_app()` ищет `.app` скачанного Chromium в `browsers/`, `_browser_pid()` спрашивает у
самого браузера через CDP (`SystemInfo.getProcessInfo`, тип `browser`) — это запасной путь,
когда `.app` не нашёлся.

### `app/cleanup.py`

Из списка мест для чистки убрать `ROOT / "launcher"` — папки больше нет.

### `app/captcha.py`, `app/human.py`

Только слова в описаниях: «уведомление Windows» → «уведомление системы», «одно событие Windows
отдаёт браузеру за 15–30 мс» → «система отдаёт». Код не меняется.

### `requirements.txt`

Убрать `pythonnet` и `pystray`. Остальное оставить как есть — версии библиотек в форке и в
исходнике должны совпадать, иначе на Mac вы будете ловить чужие ошибки.

Важно: `bin/bootstrap.sh` считает sha256 от `requirements.txt` и хранит её в
`runtime/installed.txt`. Любая правка файла — и установщик при следующем запуске сам доставит
новое. Ничего дополнительно делать не надо.

### Тесты

| Файл | Правка |
|---|---|
| `tests/__init__.py` | в описании: `tests/run_tests.command` вместо `tests\run_tests.bat`, `runtime/venv/bin/python` вместо `runtime\python\python.exe` |
| `tests/support.py` | затвор браузерных тестов — один `needs_browser` вместо повторённого четыре раза `skipUnless(has_browser(), …)`. Переменная среды `RW_SKIP_BROWSER_TESTS` с непустым значением отключает их нарочно, и причина пропуска тогда говорит именно это. Нужно, чтобы CI на каждый пуш гонял только быстрый набор, — см. раздел 7 |
| `tests/test_avito_nav.py`, `test_captcha.py`, `test_click_aim.py`, `test_slider.py` | вместо `skipUnless(has_browser(), «Chromium не установлен (setup.bat)»)` — `@needs_browser` из `tests/support.py`; в импорте `has_browser` меняется на `needs_browser` |
| `tests/test_cleanup.py` | тест «чистится только папка программы» больше не верен: чистится и код (`ROOT`), и рабочая папка (`HOME`). Проверять, что путь лежит в одном из двух, и что база, журналы, фотографии и экспорт **не** попадают в список |
| `tests/test_system.py` | новый: замок одной копии, создание папки под замок, `light_theme()` отвечает хоть что-то, тихие вызовы не падают, выбрана ровно одна система |

Тесты никогда не обращаются к настоящим сайтам и не касаются настоящей базы — это обеспечивает
`tests/support.py` (подменяет `net.Http.request` на «только 127.0.0.1» и `net.Browser.start` на
исключение). Эту защиту **не трогать**: она единственное, что отделяет прогон тестов от визита
на Авито с настоящим профилем.

## 5. Шаг 3. Оболочка — что делает каждый скрипт

Все четыре скрипта переносятся из прошлого форка почти без правок. Что в них посмотреть:

### `bin/bootstrap.sh` — установщик среды

Что делает: качает `uv` (версия прибита в начале файла), им ставит Python, библиотеки из
`requirements.txt` и Chromium для patchright. Всё — в `~/Library/Application Support/RealtyWatch`.

Нюансы, которые дались не сразу:

- **Карантин на `uv` и на Chromium.** Скачанный Chromium получает метку `com.apple.quarantine`
  и **молча не запускается**. Лечится `xattr -dr com.apple.quarantine "$BROWSERS"` сразу после
  установки. Без этого порт выглядит сломанным без всякой ошибки.
- **Кеш установщика наружу не утекает.** `uv` по умолчанию кладёт Python в `~/.local`, а кеш — в
  `~/Library/Caches/uv`, и это рушит обещание «всё в одной папке». Поэтому:
  ```bash
  export UV_PYTHON_INSTALL_DIR="$RUNTIME/python"
  export UV_PYTHON_BIN_DIR="$RUNTIME/bin"
  export UV_CACHE_DIR="$RUNTIME/cache"
  ```
  и `uv cache clean` в конце. Отдельный шаг в CI это проверяет — см. раздел 6.
- **Повторный запуск ничего не качает.** `--check` отвечает кодом 0/2; метка — sha256 от
  `requirements.txt` в `runtime/installed.txt`. На этом держится мгновенный второй запуск.
- **Процессор.** `uname -m` → `arm64` даёт `aarch64-apple-darwin`, иначе `x86_64-apple-darwin`.
- **Честные размеры.** В сообщении пользователю: качает около 300 МБ, на диске занимает около
  800 МБ (Chromium 480, Python с библиотеками 300). Если в версии 2 вырос список библиотек —
  перемерить по выводу CI (`du -sh` по подпапкам) и поправить цифры в скрипте, в `build_app.sh`
  и в `README.md`. Три места.

### `bin/launch.sh` — точка входа бандла

Он же `Contents/MacOS/RealtyWatch`. Понимает, где лежит: внутри бандла (есть
`../Resources/app`) или в папке с исходниками. Если среды нет — открывает **окно Терминала**
с установщиком, чтобы человек видел, что происходит, и выходит; установщик по окончании сам
открывает приложение (`RW_APP`). Если среда есть — сразу `exec python -m app.main`, вывод в
`logs/console.log`.

Почему Терминал, а не молчаливая установка: первый запуск идёт минуты, и приложение, которое
ничего не показывает несколько минут, выглядит сломанным.

### `build_app.sh` — собирает `.app`

Способ «appify»: бандл — это `Info.plist` + исполняемый файл в `Contents/MacOS/` + `Resources/`.
Никакой заморозки кода.

- **Что копируется в `Resources/`:** `app web assets bin requirements.txt`. **Если версия 2
  завела новую папку верхнего уровня — добавить её в этот список.** Иначе бандл соберётся,
  запустится и упадёт на `import` или на отсутствующем файле данных.
- **Версия:** `VERSION="${RW_VERSION:-$(date +%Y.%m.%d)}"`. Для релиза её передают, иначе в
  `Info.plist` попадает дата сборки.
- **Иконка:** `.icns` собирается из `assets/icon.png` средствами системы (`sips` + `iconutil`).
  Размеры больше исходника не рисуются — вышла бы размытая картинка.
- **Ad-hoc подпись** `codesign --force --deep --sign -`: карантин она не снимает, но бандл
  выглядит целым и не ругается при переносе.
- Бандл получается около 2 МБ и не зависит от процессора: среда приходит при первом запуске.

### `build_dmg.sh` — собирает то, что пересылают

Внутри образа — приложение и симлинк на `/Applications` с русским именем «Программы».
Вся установка для получателя: перетащить одно на другое. `hdiutil create ... -format UDZO`.

### `start.command` и `tests/run_tests.command`

Двойной клик из папки с исходниками: запуск программы и прогон тестов. Сборка для этого не нужна —
удобно при разработке.

## 6. Чего не делать

| Соблазн | Почему нет |
|---|---|
| Заморозить код в бандл (PyInstaller, py2app) | у py2app известная заноза: внутри бандла Playwright не находит браузер. И бандл становится платформенным, тяжёлым, а код — неправимым без пересборки |
| Положить Python и Chromium внутрь `.app` | бандл на 800 МБ, который нельзя обновить по частям, и `.app` всё равно не может писать внутрь себя |
| Сделать значок в строке меню | на macOS и `pywebview`, и `pystray` требуют главный цикл приложения. Это известный конфликт, не «надо доделать» |
| Сделать «Закрыть» сворачиванием: окно прячется, программа живёт в Dock | предложено владельцу 5 ноября 2026 и отклонено им. Главное Dock делает и так, а уведомления на macOS приходят всегда, значок им не нужен. Чтобы закрытие не завершало программу, нужен перехват `closing` плюс повторное открытие из Dock — это Cocoa, и прогон на раннере не проверит ни строчки: графического сеанса там нет. Цена ошибки — программа без окна, которую не закрыть иначе как «Завершить принудительно». Если решение переменится, делать это отдельным шагом и смотреть на живом Маке, а не внутри релиза |
| Писать данные рядом с `.app` | ломает подпись и не работает, когда приложение в «Программах», а человек не администратор |
| Ускорить ожидания страницы в тестах | ожидание страницы (`net._still`, `net._reacted`, `human._settled`) — это не «пауза человека». Если его масштабировать `TIME_SCALE`, тесты станут зелёными, а программа начнёт бить мышью мимо ссылок на медленной машине. Ровно это и поймал CI — трижды. Во второй раз (ноябрь 2026) оказалось, что окно промаха в тестах само по себе в тридцать раз уже живого: движение курсора `TIME_SCALE` ускоряет, а перекладку страницы — нет. Раннер промахивался и в эти 20 мс, два прогона из четырёх, — значит на живом сайте, где у страницы на это почти секунда, промах был обычным делом. Вывод не «подкрутить ожидание», а «курсор обязан сверяться с целью перед нажатием». В третий раз (`1539def`) вскрылась и обратная сторона: само ожидание принимало редкие кадры за остановку кусочка пазла — «медленно» не значит «доехал» |
| Снять защиту из `tests/support.py`, чтобы тест «проверил по-настоящему» | тогда тест пойдёт на Авито с настоящим профилем. Никогда |

## 7. Где тестировать

Три уровня, по возрастанию достоверности. Первые два делаются полностью с Windows-машины.

### Уровень 1. Юнит-тесты на Windows

Форк работает и на Windows, поэтому почти все тесты гоняются прямо здесь. Три условия:

1. `RW_HOME` в сторону временной папки — чтобы не касаться настоящих данных;
2. корень форка **первым** в `sys.path`, а корень Windows-версии — убрать, иначе `import app`
   возьмёт чужой код;
3. гонять **не системным** Python, а тем, что принёс установщик Windows-версии:
   `RealtyWatch_Win\runtime\python\python.exe` — в нём уже лежат Pillow, lxml и браузерный
   слой. В системном их нет, и набор падает на `ModuleNotFoundError: No module named 'PIL'` ещё
   до первого теста. Проверять наличие надо по `patchright`, а не по `playwright`: программа
   пользуется первым, и `import playwright` даст ложный отказ.

Тестам с браузером нужен Chromium. Качать второй раз не надо: достаточно сделать в
`$RW_HOME/browsers` junction на `RealtyWatch_Win/browsers` (чтение чужой папки правилом не
запрещено):

```
# PowerShell; в cmd то же самое делает mklink /J
New-Item -ItemType Junction -Path "$env:RW_HOME\browsers" -Target "D:\Claude\RealtyWatch\RealtyWatch_Win\browsers"
```

Что здесь **не** проверяется: ничего из `app/system.py` по ветке macOS, окно, бандл, установщик.

### Уровень 2. GitHub Actions, `macos-15` — главная проверка

`.github/workflows/mac.yml`. Раннеры GitHub — настоящее железо Apple, Apple Silicon, система
15.8.x; у целевого MacBook Air M1 тот же процессор и то же поколение системы (15.7.3).
**Зелёный прогон здесь — сильное свидетельство, что на целевом Маке всё работает.**

Держать `macos-15`, а не `macos-latest`: последний со временем уедет на macOS 26.

Прогон проверяет по порядку:

| Шаг | Что доказывает |
|---|---|
| `sw_vers`, `uname -m` | это правда тот Mac, на который мы рассчитываем |
| `bash bin/bootstrap.sh` | среда доставляется с нуля |
| `bootstrap.sh --check` | повторный запуск ничего не качает |
| `unittest discover` | на пуш — быстрый набор; по кнопке «Run workflow» — все, включая браузерные, на настоящем Chromium под macOS. Шаг падает, если пропустилось не то, что задумано |
| `./build_app.sh` | бандл собирается |
| проверка бандла | запускатор исполняемый, иконка на месте, код внутри, `CFBundleIdentifier` и версия в `Info.plist`, `codesign -dv`, размер |
| `python -m app.main --server` + `curl` | сервер поднимается, `/api/settings` отвечает, страница отдаёт `<title>RealtyWatch</title>` |
| «Всё лежит в одной папке» | `du -sh` по подпапкам и **падение**, если появились `~/Library/Caches/uv`, `~/.cache/uv`, `~/Library/Caches/ms-playwright`, `~/.local/share/uv` |
| `ditto -c -k --keepParent` | zip с сохранёнными правами на запуск (обычный artifact их теряет) |
| `build_dmg.sh` + `hdiutil verify` + `attach`/`ls`/`detach` | образ не просто целый — внутри лежит запускаемое приложение и ярлык «Программы» |
| два артефакта | `RealtyWatch-dmg` и `RealtyWatch-app`, живут 90 дней |

#### Что гонится на пуш, а что по кнопке

Запуск сужен 8 ноября 2026 по решению владельца. Повод денежный: репозиторий приватный, минуты
macOS в Actions считаются с коэффициентом 10, и за 2–7 ноября 26 прогонов съели около 1000
оплачиваемых минут из 2000 бесплатных в месяц — при том же темпе месяц выходил за лимит вдвое.

Где эти минуты лежали, видно по разбору прогона `42429456923` (сумма шагов 283 с):

| Шаг | Время |
|---|---|
| тесты | 255 с, из них браузерные (`test_avito_nav`, `test_captcha`, `test_click_aim`, `test_slider`) — 222 |
| доставка среды | 12 с |
| сборка `.app`, проверка бандла, сервер, Корзина, `.dmg`, артефакты | 16 с |

То есть сокращать имело смысл ровно одно — браузерные тесты. Так и сделано, и вот что
получилось на деле (прогон `42433947531`, первый пуш по новым правилам): шаг тестов 27 секунд
вместо 255, весь прогон 64 секунды вместо 283. Тестов при этом выполнено столько же, 108,
из них 11 пропущено нарочно. Правило теперь такое:

- **пуш с кодом** — быстрый набор и вся сборка целиком. Браузерные классы пропускаются: шаг
  выставляет `RW_SKIP_BROWSER_TESTS=1`, и `tests/support.py` отключает по нему `@needs_browser`.
  То, что браузера в тех же файлах не требует (поиск выреза в `test_slider.GapFinder`),
  продолжает гоняться на каждый пуш;
- **кнопка «Run workflow»** (`workflow_dispatch`) — весь набор, вместе с браузерными. Этим же
  запуском собирается релизный `.dmg` (`-f version=N`), так что перед выпуском они гонятся всегда;
- **правка одних записей** (`**.md`) — не гонит ничего: `paths` исключает их.

Пропуск — это способ прогону тихо позеленеть, поэтому шаг сверяет журнал. Пропуск с причиной
«Chromium не установлен» валит прогон в любом случае: он означает, что браузер не доставил
установщик, а не что мы так решили. В быстром прогоне шаг, наоборот, падает, если нарочного
пропуска в журнале нет вовсе, — иначе незамеченная правка затвора просто вернула бы полный набор.
Третья проверка сверяется не с переменной, а с самим событием: запуск по кнопке, в котором
браузерные тесты выключены, валится. Без неё перевёрнутое условие дало бы зелёный прогон — все
остальные проверки сверяют журнал именно с переменной и ошибки в ней не увидят.

Оба пути проверены сразу после правки, и каждый — тем, что должно быть видно в журнале:

| Прогон | Что в журнале |
|---|---|
| `42433947531`, пуш | «быстрый набор: браузерные тесты пропускаются нарочно», `Ran 108 tests in 26.3s`, `OK (skipped=11)`, записи загрузки нет |
| `42434064490`, кнопка | «полный набор, вместе с браузерными», `Ran 108 tests in 294.9s`, `OK` без пропусков вовсе, загрузка пишется каждые 20 с |

Зелёного прогона тут мало: «быстрый набор» зелёный и в том случае, когда затвор сломан и
браузерные тесты не гонятся нигде. Поэтому смотреть надо на эти строки, а не на галочку.

Чего нельзя: остаться совсем без браузерных прогонов на Маке. Оба найденных дефекта — промах по
«следующей странице» и отпускание ползунка капчи на ходу — вылезли именно на занятом
`macos-15` и больше нигде. Кнопку надо нажимать, а не вспоминать. Запуск по расписанию — это
новый расход, и включать его без согласия владельца нельзя.

Запуск вручную: `gh workflow run mac.yml` (или с версией — см. раздел 8). Чтение логов:

```bash
gh run list --workflow mac.yml --limit 5
gh run view <id> --log-failed
```

Чего CI не покажет никогда: **как выглядит окно**. `pywebview`/WebKit на раннере не запускается —
там нет графического сеанса. Шрифты, тёмная тема, поведение карты, иконка в Dock — только живьём.

#### Два браузерных теста срывались на занятом раннере — оба разобраны

Это единственный автопрогон во всём репозитории: у Windows-версии его нет вовсе, её тесты
запускают руками на быстрой машине. Поэтому всё, что зависит от времени, видно только здесь —
и считать эти срывы капризами прибора нельзя. Из 24 прогонов (2–7 ноября 2026):

| Тест | Красных | Когда | Причина и правка |
|---|---|---|---|
| `test_solves_slider_itself` | 3 | 2 ноября (дважды), 6 ноября | ожидание принимало «почти не двигается» за «доехал» — `1539def` в основной, перенесён сюда |
| `test_reads_avito_like_a_person` | 2 | 2 ноября, 7 ноября | курсор нажимал по запомненной точке, не сверившись с ней — `853d581` / `1b69815` |

В одном прогоне (`41536088310`) упали оба. И там, и там причина оказалась живым дефектом, а не
особенностью раннера, и ни один из них не нашёлся по счёту зелёных прогонов: оба воспроизвели
нарочно, на любой машине.

**Пагинация.** Курсор шёл к запомненной точке почти секунду и нажимал, ни разу не сверившись с
тем, что под ним. Теперь сверяется. Доказательство — тест `test_click_aim`, который воспроизводит
промах нарочно и на прежнем поведении падает.

**Ползунок.** Все три падения — одна и та же проверка `max(lags) <= 1.5`, значения 2.2, 1.7, 1.8:
ручку отпускали, пока кусочек ещё догонял. `_settled` сравнивал каждый замер с предыдущим и считал
сдвиг меньше 0.25 px за «доехал». Но страница подтягивает кусочек к ручке понемногу с каждым
нарисованным кадром: когда кадров мало, он за замер сдвигается на доли пикселя, хотя ехать ему ещё
далеко, — два почти равных замера тогда значат «страница не рисовала», а вовсе не «доехал». При
совсем редких кадрах два замера попадают в один и тот же кадр и дают сдвиг ровно 0. Теперь стояние
меряется по времени (сдвинулся меньше `STILL = 0.05` px за `CALM_S = 0.35` с), а по недоехавшему
замеру поправка не делается вовсе — ждут ещё.

Воспроизводится без нагрузки и без везения: в имитации GeeTest `requestAnimationFrame` заменён на
`setTimeout(follow, FRAME)`, частота кадров задаётся ключом `frame` в `Site.state`. Запоздание
перед отпусканием / ошибка наводки на прежнем ожидании: 16 мс — 0.2 / 0.6 px, 25 мс — 0.9 / 0.6,
33 мс — 3.4 / 20 (срыв 2 из 2), 100 мс — 10 / 25 (срыв 3 из 3). Числа CI (1.7–2.2) лежат между
25 и 33 мс: раннер под load average 7.65 рисовал страницу 35–40 раз в секунду. А ошибка наводки
20 px — это уже не придирка теста: на живом Авито пазл при этом не принимают.

Арифметика, из-за которой легко ошибиться: при частоте 3 из 24 три зелёных прогона подряд
случаются сами по себе в двух случаях из трёх. **Зелёный прогон тут не доказывает ничего** —
о починке говорит только найденная причина и тест, который её воспроизводит. Для обоих дефектов
такой тест теперь есть (`test_click_aim`,
`test_slow_page_is_not_mistaken_for_a_stopped_piece`), и красного прогона ждать больше не нужно.

Если по времени сорвётся что-то новое, основной ветке нужны: полный текст падения (в нём
`Site.state['lags']` и строка «пазл: вырез x=… (уверенность …), довели с ошибкой … px», а с
`1539def` ещё и «, кусочек ещё ехал», если отпустили на ходу), время прогона и загрузка раннера —
её `mac.yml` пишет каждые 20 секунд всё время прогона, поэтому по метке времени видно число под
нужным тестом. **Картинок задания в прогоне не будет:** `test_solves_slider_itself` подменяет
`b.keep` заглушкой, которая лишь считает размеры, и фон с кусочком на диск не попадают. Нужны
картинки — менять надо тест, а не прогон.

И связь, которая важнее самих тестов: у владельца пазл-капча на живом Авито до сих пор не
проходится. Оба найденных дефекта из тех, что живьём проявляются сильнее, чем в тестах: там у
страницы на перекладку целая секунда, а не двадцать миллисекунд. Поэтому красный прогон здесь
ценнее зелёного.

### Уровень 3. Живой Mac

Единственное, что остаётся человеку:

1. окно открылось, интерфейс читается, тёмная тема не ломает вид;
2. иконка в Dock и в «Программах» своя;
3. сбор с настоящего сайта доходит до конца и капча проходится;
4. уведомление приходит, звук слышно.

## 8. Как выпустить

Релиз в репозитории **один на версию**, общий для Windows и macOS: тег `vN`, в нём два файла.
Windows-сборку кладёт тот, кто ведёт основную ветку; задача порта — положить рядом `.dmg`.

**Правило, которое важнее остальных: тег должен указывать на тот коммит, из которого собран
`.dmg`.** Иначе через полгода невозможно понять, что внутри файла.

Порядок:

```bash
# 1. всё запушено, прогон на этом коммите зелёный
git log --oneline -1
gh run list --workflow mac.yml --limit 1

# 2. собрать с номером версии (иначе в Info.plist попадёт дата)
gh workflow run mac.yml -f version=2.0

# 3. дождаться и взять артефакт
gh run list --workflow mac.yml --limit 1          # запомнить id
gh run download <id> -n RealtyWatch-dmg -D /tmp/rw

# 4. назвать так, чтобы имя говорило всё
mv /tmp/rw/RealtyWatch.dmg /tmp/rw/RealtyWatch-2.0-macos.dmg

# 5. положить в релиз (--clobber только если перезаливаете)
gh release upload v2.0 /tmp/rw/RealtyWatch-2.0-macos.dmg

# 6. убедиться, что в релизе лежит ровно то, что собирали
gh release view v2.0 --json assets --jq '.assets[] | "\(.name) \(.size)"'
shasum -a 256 /tmp/rw/RealtyWatch-2.0-macos.dmg
```

Так был выпущен `RealtyWatch-1.0-macos.dmg` (1 416 100 байт) в релизе `v1.0`. В 1.3 правило
выполнено для обеих половин сразу: тег `v1.3` стоит на `9af8d39`, и из него собраны и архив
Windows, и образ Мака (1 462 758 байт, 108 тестов из 108).

**Ловушка, на которой легко ошибиться в «что нового».** У 1.2 половины собраны из разных
коммитов: архив Windows из `287af1b`, на который указывает тег, а образ Мака — из `2883115`,
которого в теге нет. Значит для Мака список изменений считается **не от тега предыдущей версии,
а от того коммита, из которого собран предыдущий образ**; его видно в таблице «Сборка» прошлого
релиза и внутри самого файла, в `version.txt`. Иначе в «что нового» попадает то, что пользователь
Мака получил выпуском раньше: при подготовке 1.3 так и вышло — графики с равномерной шкалой
времени уже лежали в образе 1.2, хотя по тегу выглядели новыми.

Чего не делать:

- **не переносить тег опубликованного релиза, если файлы уже скачивали.** В версии 1.0 это было
  безопасно только потому, что скачиваний было ноль. Если они есть — выпускать 2.0.1, а не
  переписывать историю: у людей на руках файл, который больше ничему не соответствует.
- не собирать релизный `.dmg` руками на своём Маке, когда есть CI: прогон заодно всё проверяет,
  и видно, из какого коммита файл.

**Репозиторий приватный.** Ссылка на релиз откроется только у соавторов. Знакомому с Маком
`.dmg` передаётся файлом — мессенджером, облаком, флешкой. Файл с флешки, кстати, не получает
метки карантина вообще.

## 9. Памятка конечному пользователю

Это можно переслать как есть — она намеренно короткая.

### Установка

> 1. Открыть `RealtyWatch.dmg` двойным кликом.
> 2. Перетащить `RealtyWatch` на «Программы».
> 3. Запустить из «Программ». Выскочит предупреждение — закрыть его кнопкой «Отменить»,
>    из него самого ничего не открыть. Затем один раз разрешить запуск: «Системные настройки» →
>    «Конфиденциальность и безопасность» → внизу «Открыть всё равно».
> 4. Первый запуск откроет окно Терминала и минут десять будет качать Python и браузер
>    (около 300 МБ). Когда напишет «готово» — программа откроется сама. Дальше запуск мгновенный.

В macOS 15 Sequoia и новее обхода через правый клик больше нет — только «Системные настройки».
Кому привычен Терминал, тому быстрее:

```
xattr -dr com.apple.quarantine /Applications/RealtyWatch.app
```

### Удаление — две папки

> 1. `RealtyWatch.app` из «Программ» в Корзину.
> 2. В Finder нажать ⇧⌘G, вставить `~/Library/Application Support/RealtyWatch` — и эту папку
>    тоже в Корзину.
>
> Больше нигде ничего не остаётся. Если база нужна — перед удалением сохранить из неё папку
> `database/` или сделать экспорт в самой программе.

В этой одной папке лежит всё: Python, Chromium, база с фотографиями, журналы, профили браузера,
настройки. Кеш установщика стирается сам сразу после установки. Отдельный шаг в CI падает, если
что-нибудь появилось снаружи, — так что обещание «всё в одной папке» не на словах.

## 11. Подводные камни, на которые уже наступали

- **CRLF.** Скрипт с `\r\n` на Mac не запускается: `bad interpreter: /bin/bash^M`. Лечится
  `.gitattributes` **до** коммита. Выглядит как поломка Mac.
- **Карантин на Chromium.** Скачанный браузер молча не стартует. `xattr -dr` в установщике.
- **Кеш `uv` наружу.** `~/Library/Caches/uv` и `~/.local` появляются сами, если не выставить
  три переменные. Проверяется шагом в CI, а не на словах.
- **Ожидания страницы, ускоренные в тестах.** Медленная машина ловит то, чего быстрая не видит.
  Так нашлись три настоящих бага, которые потом уехали и в Windows-версию: щелчок мимо «следующей
  страницы» (прямоугольник элемента, снятый на ходу, врал на целый щелчок колёсика — 100 px),
  отпускание ползунка капчи на ходу и ожидание, принимавшее редкие кадры за остановку кусочка. Если CI падает на `test_avito_nav` или `test_slider` —
  не списывайте на «медленный раннер», это баг.
- **`${{ inputs.version }}` пуст на push.** Это нормально: в `Info.plist` тогда идёт дата сборки.
  Номер версии появляется только у запуска вручную.
- **`actions/upload-artifact` теряет права на запуск.** Поэтому `ditto -c -k --keepParent`, а не
  просто загрузка папки `.app`.
- **`hdiutil verify` проверяет только контрольную сумму.** Что внутри образа лежит работающее
  приложение, доказывает только `attach` + `ls` + проверка `-x` на запускаторе.
- **Heredoc в этом окружении съедает обратные слэши.** Если скрипт пишется через `cat <<EOF`,
  `r"logs\\console.log"` превратится в `r"logs\console.log"`. Писать файлы редактором, а не
  heredoc'ом, либо собирать слэш через `chr(92)`.
- **Нотаризация.** По-настоящему «скачал и открыл» даёт только Developer ID ($99/год) +
  `notarytool`. Промежуточного не существует: либо подпись, либо один раз «Открыть всё равно».

## 12. Как переносить правки из новой версии, когда форк уже есть

Раздел 3 — про форк с нуля. Когда форк уже живёт, работа другая: не копировать папку заново,
а разобрать коммиты основной ветки и взять из них только общее. Делается так.

**1. Посмотреть, что накопилось.** Форк отстаёт от Windows-версии ровно на те коммиты, которые
её трогали:

```bash
git log --oneline <последний перенесённый коммит>..origin/main
git show --stat <коммит>
```

**2. Разделить коммиты на «общие» и «только Windows».** Признак не в названии файлов, а в сути:
трей, реестр, `winsound`, панель задач, PowerShell-установщик — только Windows. Экспорт, разбор
страниц, интерфейс, база — общее. Коммит целиком про трей не переносится вообще, даже та его
часть, что лежит в `app/settings.py` или `web/app.js`: настройка, которой не на что влиять,
хуже отсутствующей.

**3. Брать файлы из блобов, а не с диска.** В рабочей копии Windows-версии переводы строки CRLF,
в форке они обязаны быть LF. `git show` отдаёт блоб как он лежит в репозитории — уже нормализованный:

```bash
git show origin/main:RealtyWatch_Win/app/share.py > RealtyWatch_Mac/app/share.py
```

**4. Сначала узнать, какие файлы вообще расходятся.** Почти все файлы форка совпадают с
Windows-версией байт в байт — их берут целиком, и думать тут не о чем. Расходятся единицы, и список
получается одной командой: сравнить Win и Mac **на том коммите, с которого форк отстал**.

```bash
for f in app/server.py web/app.js web/dash.js; do
  diff <(git show 2883115:RealtyWatch_Win/$f) <(git show 2883115:RealtyWatch_Mac/$f) > /dev/null \
    && echo "$f: одинаковы, брать целиком" || echo "$f: расходятся, сливать"
done
```

Для расходящихся — `git merge-file`. Он знает про три состояния и сводит их сам, отмечая только
спорные места; руками в таком файле искать нечего:

```bash
git show <база>:RealtyWatch_Win/web/app.js  > base     # общий предок
git show <новый>:RealtyWatch_Win/web/app.js > theirs   # он же с правками основной ветки
git show <база>:RealtyWatch_Mac/web/app.js  > mine     # моё расхождение
cp mine out && git merge-file -L "мой Mac" -L "база" -L "их Win" out base theirs
```

Конфликтов выходит два-три на партию, и все — ровно в тех строках, где форк расходится намеренно.
Правило простое: **брать сторону основной ветки**, а своё расхождение вносить в её новый текст
заново (путь через `/`, Finder вместо Проводника, убранная настройка трея). Исключение — строка
импортов: её объединять, иначе пропадёт либо наш `system`, либо их новый модуль.

**Другой случай — когда общий коммит идёт перед виндовым и трогает те же файлы.** Тогда слияние
не нужно: достаточно взять файл по состоянию на общий коммит, а не на `origin/main`.

```bash
# в app.js есть и экспорт избранного (нужен), и галочка трея (не нужна) —
# берём состояние на коммите про избранное, до коммита про трей
git show f8285d5:RealtyWatch_Win/web/app.js > RealtyWatch_Mac/web/app.js
```

Проверить, что виндовое не просочилось, — поиском по ключевым словам:

```bash
grep -c -E "s-ui|sTray|tray_on_close" RealtyWatch_Mac/web/app.js   # должен быть 0
```

**5. Сверить размер правки с оригиналом.** `git diff --stat` по форку должен совпасть с
`git show --stat` общего коммита по тем же файлам. Не совпало — значит, прихватили лишнее.

**6. Пройти по известным местам, где форк расходится.** Это короткий список, и он не меняется:

| Файл | Что проверить |
|---|---|
| `app/paths.py` | новый путь пишется в `HOME`, а не в `ROOT` |
| `app/system.py` | новый системный вызов — сюда, а не в вызывающий файл |
| `app/about.py` | `PY_LIBS` обязан совпадать с `requirements.txt` форка: `pythonnet` и `pystray` в нём есть, у нас нет. Тест `test_about` сверяет список в обе стороны и падает при расхождении |
| `requirements.txt` | версии библиотек совпадают с исходником, лишних двух нет |
| `build_app.sh` | новая папка верхнего уровня добавлена в список копирования |
| `app/trash.py` | не переносится вовсе: у форка свой, см. раздел 4 |
| четыре браузерных теста | строка `@unittest.skipUnless(has_browser(), …)` в форке заменена на `@needs_browser`. Правка из основной ветки её не тронет, но при слиянии строка будет выглядеть конфликтом — оставлять нашу |
| `web/app.js`, `web/dash.js`, `web/index.html` | тексты: `database\backups` → путь через `/`; «Проводник» → Finder; «корзина Windows» → «Корзина»; «уведомления Windows» → «уведомления системы»; «свёрнуто в трей» → «свёрнуто в Dock» |

Замены в текстах удобно делать не руками, а списком «было → стало», где каждая строка обязана
найтись заданное число раз. Не нашлась — скрипт падает и не пишет ничего: молча разойтись с
основной веткой хуже, чем упасть.

**7. Номер версии.** Windows-сборщик кладёт рядом с кодом `version.txt`, окно «О программе» читает
его первую строку. В форке этот файл пишет `build_app.sh` в `Contents/Resources/` — в том же виде
(`RealtyWatch 1.1, сборка 2026-11-05, коммит abc1234`), чтобы разбор остался общим. Из репозитория
программа запускается без `version.txt` — версия просто не показывается, как и на Windows.

**8. Общий рабочий каталог.** Windows-версия и форк лежат в одной папке и в одном репозитории, и
обе сессии коммитят в `main`. Поэтому `git add -A` опасен: он подхватит чужие незакоммиченные
файлы. Добавлять только свои пути:

```bash
git add RealtyWatch_Mac .github .gitattributes .gitignore
```
